## Перед изменением интерфейса

1. Уточнить границы поручения по текущему чату и статусу проекта. Прочитать документацию затронутого компонента.
2. Загрузить актуальный навык Figma Design to Code перед `get_design_context`; перед `use_figma` — навык Figma Use. Использовать схему инструментов текущей сессии, не копировать устаревшие параметры из примеров.
3. Получить свежий контекст нужного узла и screenshot. Для большого экрана разбирать секции; не запрашивать весь файл повторно без необходимости. Старый PDF, память и локальный snapshot — контекст, а не подтверждение актуальности макета.
4. Проверить существующие компоненты, варианты и токены. Сначала переиспользовать библиотеку; переносить изменения общих компонентов с проверкой `/ui-kit/` и всех затронутых мест.
5. При проблеме сохранения Figma подтвердить синхронизацию и перечитать источник. Не считать undo-эксперименты или исчезновение предупреждения утверждением дизайна.
6. Экспортировать оригиналы способом, указанным Figma. Проверить тип содержимого: HTML-ответ не является SVG/PNG. Сохранять ресурсы локально, без временных URL в коде. Исходную геометрию SVG не перерисовывать.

Перенос в код не разрешает менять исходный Figma-файл. Для изменения самого дизайна нужно соответствующее поручение пользователя. Если MCP недоступен, описать конкретный блокер; работать по snapshot только в пределах задачи, явно указав, что свежая сверка не выполнена.

## Реестры

`design/figma-source.json`: fileKey/nodeId, дата получения, реальные размеры и section IDs, качество контекста и существующий contextFile. `captured` и `high-fidelity` ставить только после фактического получения данных. Не обновлять дату проверки без новой проверки.

`design/assets.json`: id, исходный nodeId, kind (`source-image`, `exported-svg`, `exported-raster`), непустой localPath в public/assets, slots с nodeId и sectionNodeId. Для новых/изменённых ресурсов фиксировать места использования, размеры и размещение. Реестры UI и отдельных компонентов дополняют реестр главной.

## Визуальная приёмка

Сравнить с актуальным screenshot при ширине 1470 px (или новой измеренной ширине): контейнер, поля, высоты и порядок секций, шрифты и переносы, кадрирование, слои, цвета, hover/focus и SVG viewBox. Затем проверить Desktop 1366/1920 px, загрузку ресурсов и горизонтальное переполнение.

Проверить якоря, телефонные ссылки, Tab/Enter/Space, disabled-состояния и reduced motion. Для будущих диалогов — Escape и возврат фокуса; для форм — ошибки и реальное подтверждение доставки. Не заявлять работу неподключённых действий.

Мобильные размеры и композицию не придумывать: мобильный дизайн готовит пользователь. Проверка desktop не считается проверкой mobile. Исторические интервалы 120 px не применять ко всем секциям автоматически: актуальные значения брать из соответствующего узла.
