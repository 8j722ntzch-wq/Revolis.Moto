# Публикация на hoster.by

Подготовлено 23.10.2026. Workflow: `.github/workflows/deploy-hoster.yml`.
Сборка Astro выполняется в GitHub Actions, на хостинг передаётся только содержимое `dist/`. Node.js на хостинге для статических страниц не нужен.

## Secrets

В Settings → Secrets and variables → Actions → Repository secrets должны быть:

| Название | Значение |
| --- | --- |
| FTP_SERVER | Имя FTP-сервера hoster.by без протокола и пути; должно совпадать с именем в сертификате FTPS |
| FTP_USERNAME | Полный логин FTP-пользователя из панели hoster.by |
| FTP_PASSWORD | Пароль этого FTP-пользователя |
| FTP_SERVER_DIR | Каталог сайта относительно корня, видимого FTP-пользователю, обязательно с `/` в конце |

Названия выбраны для этого workflow: наличие и значения созданных пользователем secrets пока не проверены. Не присылайте пароль в чат и не записывайте его в репозиторий.

Обсуждавшийся каталог `/www/revolis.by/` подходит только если он действительно виден после входа по FTP. Если домашняя директория FTP-пользователя уже указывает на каталог сайта, нужен `/`. Проверить каталог в FTP-клиенте до первого релиза. Не подставлять системный путь хостинга без проверки FTP-корня.

Используется явный FTPS, порт 21, строгая проверка сертификата. Это пока не проверено на конкретном аккаунте hoster.by. Если в FTP_SERVER указан IP, сертификат может ему не соответствовать: используйте имя сервера из панели/ответа поддержки. SSL-сертификат домена сайта и сертификат FTP-сервера — разные настройки. При ошибке сертификата исправлять имя сервера или настройки у провайдера, а не отключать проверку.

## Первый релиз

1. Сверить четыре названия secrets, FTP-каталог и поддержку FTPS на порту 21. Сделать резервную копию существующего сайта, если он уже есть.
2. Когда сайт готов к релизу, перенести `development` в `master` через существующий Pull Request. Само добавление workflow в development ничего не загружает.
3. Push/merge в master автоматически запускает Deploy to hoster.by. Открыть Actions и проверить выполнение всех шагов.
4. После успешной загрузки проверить https://revolis.by/, каталог, SKU, стили и изображения. Убедиться, что корень сайта в панели хостинга соответствует FTP-каталогу; удалить стандартную заглушку index.php вручную, если она перекрывает index.html, после резервного копирования.
5. Проверить HTTPS и отображение ошибочных URL. Кастомный документ 404.html настраивается отдельно в панели веб-сервера, если она не использует его автоматически.

Ручной workflow_dispatch разрешает загрузку только из master. Сейчас default branch — legacy main; кнопка ручного запуска может не отображаться, пока workflow отсутствует в default branch. Для первого релиза используйте штатное слияние в master. Не менять main или default branch ради этой задачи без отдельного решения.

## Поведение и ограничения

Перед загрузкой проверяются наличие secrets, Astro, комплектность дизайн-ресурсов, тесты и сборка. Ошибка останавливает публикацию. Параллельные загрузки сериализованы; текущая загрузка не прерывается новым push.

FTP Deploy Action синхронизирует файлы, используя `.ftp-deploy-sync-state.json`: обновляет изменённые и удаляет ранее опубликованные файлы, которых больше нет в сборке. Полная очистка каталога выключена. Не удалять state-файл без понимания последствий. Публикация по FTP не атомарна: при сбое возможна частичная загрузка, потребуется повторный запуск или восстановление копии.

Внешние файлы, например серверный обработчик или настройки хостинга, не добавляются этим workflow. Приём заявок остаётся неподключённым; публикация статики не создаёт backend. Текущие noindex и служебные страницы сборки не меняются. Готовность к индексации и состав публичных страниц проверить перед релизом.

Документация используемого action: https://github.com/SamKirkland/FTP-Deploy-Action

## Проверка без публикации

`Check hoster.by FTPS (read only)` запускается при изменении своего YAML или `scripts/check-hoster-ftps.py` в development. Повторить после исправления secrets можно через Re-run all jobs у этого запуска, без изменения master/main. Проверка использует только стандартную библиотеку Python и GitHub secrets: TCP/21, AUTH TLS со строгим сертификатом, вход, PROT P, CWD и пассивный LIST. Файлы не записываются и не удаляются; значения secrets, имена файлов и ответы сервера не выводятся. При ошибке сертификата проверка не переходит к входу. Успех не подтверждает право записи или соответствие FTP-каталога document root сайта. Отсутствующий завершающий `/` не мешает проверить каталог, но делает результат неуспешным до исправления secret для деплоя.
