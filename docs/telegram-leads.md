# Отправка заявок в Telegram

## Состояние — 03.11.2026

Секреты GitHub Actions `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` проверены: бот revvi_revolis_bot, личный получатель подтверждён отдельным кодом. Тестовое сообщение через Telegram API отправлено с разрешения владельца. Это не проверка отправки с сайта.

Подготовлен PHP endpoint `server/leads.php` и вспомогательный `server/lead-validation.php`. Размещаются вместе в `~/www/revolis.by/api/`. В Astro указан `/api/leads.php` по умолчанию. PDF политики обработки персональных данных пока не предоставлен; кнопки остаются выключенными существующей проверкой готовности.

Серверная часть ещё не установлена на хостинг. Необходимо проверить PHP 8+ и расширение cURL на реальном хостинге до загрузки секретов. Локальный Astro dev/preview PHP не исполняет.

## Установка после получения PDF

1. Разместить утверждённый PDF в `public/documents/` и установить `PUBLIC_PERSONAL_DATA_POLICY_URL` при сборке релиза; не подменять другой политикой.
2. Проверить выполнение минимального PHP probe по HTTPS без секретов; удалить probe. Убедиться, что `dirname(__DIR__, 3)` для endpoint соответствует домашнему каталогу SFTP.
3. Создать `~/revolis-private/` (0700), конфигурацию `leads.php` (0600), возвращающую PHP-массив `token`, `chat_id`, `enabled => true`. Значения брать из Actions secrets, не печатать и не включать в артефакты/репозиторий. Каталог должен находиться вне document root. Создать `lead-rate-limit.json` (0600, `{}`); проверить доступ записи PHP.
4. Загрузить оба PHP-файла в `/api/` с проверкой хеша и резервной копией. Публикацию страниц выполнять обычным release workflow development → master; не включать автоматический выпуск development.
5. Отправить согласованную тестовую заявку через реальную форму, проверить Telegram и окно благодарности. Проверить ошибку/повторную отправку и варианты банков. Только после этого считать интеграцию рабочей.

## Контракт и ограничения

POST JSON, только Origin `https://revolis.by` / `https://www.revolis.by`, максимум 4096 байт. Обязательны name, phone, consent=true, intent, source. modelId и bank необязательны. «Любой» передаётся отсутствием bank. Данные приходят обычным текстом, без интерпретации Markdown/HTML.

Сервер проверяет типы, размеры, телефон, допустимые intent/bank и отсутствие управляющих символов. IP берётся из REMOTE_ADDR, не из недоверенных forwarded-заголовков. В приватном rate-limit файле хранятся только HMAC IP, счётчики и время: максимум 5 попыток за 10 минут, минимум 30 секунд между ними. Прокси-хостинг с общим REMOTE_ADDR требует отдельной настройки доверенных прокси перед запуском. Origin-проверка не заменяет антиспам; при реальном спаме потребуется дополнительная защита.

Ответ `{ "ok": true }` возвращается только после HTTP 200 и ok=true от Telegram для настроенного chat_id. Ошибки дают соответствующий HTTP-код и `{ "ok": false }`; токен и персональные данные не включаются в ответ. Не повторять автоматически запрос после таймаута: сообщение могло быть доставлено, хотя подтверждение потерялось.

Проверки: `php tests/server/leads.test.php`; workflow `check-leads.yml` дополнительно проверяет синтаксис PHP и HTTP-отказы. UI- и сборочные проверки проекта остаются обязательными. Проверка секретов отдельно: `check-telegram.yml`; код привязки имеет ограниченный срок доступности в Telegram updates, поэтому этот первоначальный check не является постоянным мониторингом.
