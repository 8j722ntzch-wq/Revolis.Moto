# Фотографии и адаптивные изображения

Исходники остаются в `public/assets/` по прежним адресам для сохранения происхождения Figma и повторного экспорта. Страницы запрашивают производные WebP из `public/assets/optimized/`; оригинальные SVG не изменяются. Исходники PNG не используются как fallback при наличии обработанной версии.

Запустить `npm ci` (с optional dependencies Astro, включая Sharp), затем `npm run images:prepare`. Обработчик читает PNG/JPEG/WebP вне папки optimized, сохраняет прозрачность, исправляет ориентацию и создаёт ширины 160/320/480/768/1200/1920/2560 px, без увеличения исходника. WebP quality 85, alphaQuality 100. Реальные размеры и размеры файлов записаны в `src/data/image-variants.json`. После добавления или замены фото повторить обработку, сборку и экспорт затронутых превью; сгенерированные файлы коммитятся вместе с manifest.

`src/lib/responsive-images.ts` определяет src/srcset/sizes. Миниатюры ограничены 480 px, карточки 1200 px, большие изображения 2560 px (или меньшим исходным размером). Браузер выбирает вариант по ширине блока и плотности экрана. Размеры источника ограничивают качество: маленькое фото не растягивается искусственно при обработке.

Для SKU положить исходники в `public/assets/products/<model-id>/`, заполнить photos (Hero) и galleryPhotos (отдельная нижняя галерея), как описано в product-pages.md. URL src указывает на исходник: общий компонент автоматически разрешает WebP из manifest. Главное фото загружается приоритетно, остальные лениво; полноэкранное фото загружается при открытии просмотра. При переключении миниатюры Hero получает собственный srcset, а не маленькую картинку из миниатюры. Ссылки галереи ведут на максимальный WebP.

Оригинальные фотографии семи SKU ещё ожидаются; механизм подготовлен без подстановки чужих снимков. SVG и композиция страниц сохранены.
